# {metadata.title}

These API routes allow you to track workflow executions in your MedusaGo application.

Depending on the workflow engine you use, executions may only be retained for a short while, or only until the MedusaGo application is restarted.

## GET /admin/workflows-executions

**List Workflows Executions**

Retrieve a list of workflows executions. The workflows executions can be filtered by fields such as `id`. The workflows executions can also be sorted or paginated.

**Authentication:** secret API key (HTTP Basic authorization), cookie session, JWT bearer token.

## POST /admin/workflows-executions/\{workflow_id\}/steps/failure

**Fail a Step in a Workflow's Execution**

Set the status of a step in a workflow's execution as failed. This is useful for long-running workflows.

**Authentication:** secret API key (HTTP Basic authorization), cookie session, JWT bearer token.

**Path parameters**

<TypeList
  types={[
    { name: "workflow_id", type: "`string`", optional: false, description: "The workflows execution's workflow id." }
  ]}
/>

**Request body** (`application/json`)

<TypeList
  types={[
    { name: "transaction_id", type: "`string`", optional: false, description: "The workflows execution's transaction ID." },
    { name: "step_id", type: "`string`", optional: false, description: "The ID of the step whose status was changed." },
    { name: "response", type: "`any`", optional: true, description: "Sets the step's response. It accepts any type." },
    { name: "compensate_input", type: "`any`", optional: true, description: "Sets the compensation function's input. It accepts any response." },
    { name: "action", type: "`\"invoke\"` \\| `\"compensate\"`", optional: true, description: "Whether to invoke or compensate the step." }
  ]}
/>

**Request examples**

<CodeTabs group="api-sample">

```bash
  "transaction_id": "{value}",
  "step_id": "{value}"
}'
```

  </CodeTab>
</CodeTabs>

**Responses**

<TypeList

## GET /admin/workflows-executions/\{workflow_id\}/subscribe

**Subscribe to a Workflow's Execution**

Subscribe to a workflow's execution to receive real-time information about its steps, status, and data.
This route returns an event stream that you can consume using the [EventSource API](https://developer.mozilla.org/en-US/docs/Web/API/EventSource).

**Authentication:** secret API key (HTTP Basic authorization), cookie session, JWT bearer token.

**Path parameters**

<TypeList
  types={[
    { name: "workflow_id", type: "`string`", optional: false, description: "The workflows execution's workflow id." }
  ]}
/>

**Request examples**

<CodeTabs group="api-sample">
  <CodeTab label="cURL" value="curl">

```bash
curl 'http://localhost:9000/admin/workflows-executions/{workflow_id}/subscribe' \
-H 'Authorization: Bearer {jwt_token}'
```

  </CodeTab>
</CodeTabs>

`200` Stream of the step's status. The response body has the content type `text/event-stream`.

## GET /admin/workflows-executions/\{workflow_id\}/\{transaction_id\}/subscribe

**Subscribe to Workflow Execution Events**

Subscribe to workflow execution events for a specific workflow and transaction. This endpoint establishes a Server-Sent Events (SSE) connection, allowing clients to receive real-time updates about the workflow execution. The events include details such as the event type, workflow ID, transaction ID, step information, response, result, and any errors that occur during the execution.

**Authentication:** secret API key (HTTP Basic authorization), cookie session, JWT bearer token.

**Path parameters**

<TypeList
  types={[
    { name: "workflow_id", type: "`string`", optional: false, description: "The ID of the workflow to subscribe to." },
    { name: "transaction_id", type: "`string`", optional: false, description: "The ID of the workflow execution transaction to subscribe to." }
  ]}
/>

**Request examples**

<CodeTabs group="api-sample">
  <CodeTab label="cURL" value="curl">

```bash
curl 'http://localhost:9000/admin/workflows-executions/{workflow_id}/{transaction_id}/subscribe' \
-H 'Authorization: Bearer {access_token}'
```

  </CodeTab>
</CodeTabs>

**Responses**

`200` OK

`400`, `401`, `404`, `409`, `422`, `500`: an [error response](/api/admin#errors) is returned.
