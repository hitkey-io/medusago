# {metadata.title}

A view configuration is a saved data-table view for an entity, such as products or orders. It lets admin users customize how a table shows its data, then save that customization as a reusable view.
These API routes allow admin users to manage the system default and personal views.

## GET /admin/views/entities

**List Views**

Retrieve a list of views. The views can be filtered by fields such as `id`. The views can also be sorted or paginated.

<Note title="Feature flag">

This API route is only available when the `view_configurations` feature flag is enabled. Set the `MEDUSA_FF_VIEW_CONFIGURATIONS` environment variable to `true` to enable it.

</Note>

**Authentication:** secret API key (HTTP Basic authorization), cookie session, JWT bearer token.

**Request examples**

<CodeTabs group="api-sample">
  <CodeTab label="JS SDK" value="js-sdk">

```ts
import Medusa from "@medusajs/js-sdk"

export const sdk = new Medusa({
  baseUrl: import.meta.env.VITE_BACKEND_URL || "/",
  debug: import.meta.env.DEV,
  auth: {
    type: "session",
  },
})

sdk.admin.views.listEntities()
.then(({ entities }) => {
  console.log(entities)
})
```

  </CodeTab>
  <CodeTab label="cURL" value="curl">

```bash

-H 'Authorization: Bearer {access_token}'
```

## POST /admin/views/\{entity\}/configurations/active

**Make View Configuration Active**

Make a view configuration active. This will set the given view configuration as the active one for the specified entity for the admin user. An admin user can only set their own configurations as active. If the view configuration ID is `null`, the active view configuration will be cleared, and the `code` or system default view configuration type will be used as the active view.

</Note>
