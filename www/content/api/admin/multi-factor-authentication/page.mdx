# {metadata.title}

Multi-factor authentication (MFA) adds an extra layer of security to admin accounts by requiring additional verification factors during login, such as a TOTP code or a recovery code.
These API routes allow admin users to manage their MFA factors, challenges, and recovery codes.

## POST /auth/mfa/challenges/\{id\}/verify

**Verify a Multi-Factor Authentication (MFA) Challenge**

Verify a multi-factor authentication (MFA) challenge issued during login. On success, this
completes the authentication flow and returns a JWT token that can be used to authenticate
subsequent requests.

**Authentication:** none.

**Path parameters**

<TypeList
  types={[
    { name: "id", type: "`string`", optional: false, description: "The MFA challenge's ID." }
  ]}
/>

**Request body** (`application/json`)

<TypeList
  types={[
    { name: "method", type: "`string`", optional: false, description: "The MFA method used to verify the challenge (for example, `totp` or `recovery-code`)." },
    { name: "code", type: "`string`", optional: false, description: "The verification code generated by the chosen MFA method." }
  ]}
/>

**Request examples**

<CodeTabs group="api-sample">
  <CodeTab label="JS SDK" value="js-sdk">

```ts
import Medusa from "@medusajs/js-sdk"

export const sdk = new Medusa({
  baseUrl: import.meta.env.VITE_BACKEND_URL || "/",
  debug: import.meta.env.DEV,
  auth: {
    type: "session",
  },
})

const result = await sdk.auth.login("user", "emailpass", {
  email: "user@example.com",
  password: "secret"
})

if (typeof result === "object" && "mfa_challenge" in result) {
  await sdk.auth.mfa.verifyChallenge(result.mfa_challenge.id, {
    method: "totp",
    code: "123456"
  })
}
```

  </CodeTab>
  <CodeTab label="cURL" value="curl">

```bash
curl -X POST 'http://localhost:9000/auth/mfa/challenges/{id}/verify' \
-H 'Content-Type: application/json' \
--data-raw '{
  "method": "{value}",
  "code": "{value}"
}'
```

  </CodeTab>
</CodeTabs>

**Responses**

`200` OK

`400`, `401`, `404`, `409`, `422`, `500`: an [error response](/api/admin#errors) is returned.

## GET /auth/mfa/factors

**List Multifactor Authentication (MFA) Factors**

Retrieve the list of multi-factor authentication (MFA) factors registered for the authenticated user,
including both pending (not yet verified) and enabled factors.

**Authentication:** none.

**Request examples**

<CodeTabs group="api-sample">
  <CodeTab label="JS SDK" value="js-sdk">

```ts
import Medusa from "@medusajs/js-sdk"

export const sdk = new Medusa({
  baseUrl: import.meta.env.VITE_BACKEND_URL || "/",
  debug: import.meta.env.DEV,
  auth: {
    type: "session",
  },
})

const { mfa_factors } = await sdk.auth.mfa.list()
```

  </CodeTab>
  <CodeTab label="cURL" value="curl">

```bash
curl 'http://localhost:9000/auth/mfa/factors'
```

  </CodeTab>
</CodeTabs>

**Responses**

`200` OK

`400`, `401`, `404`, `409`, `422`, `500`: an [error response](/api/admin#errors) is returned.

## POST /auth/mfa/factors

**Start Multi-Factor Authentication (MFA) Factor Enrollment**

Start the enrollment of a new multi-factor authentication (MFA) factor for the authenticated
user. The response contains the factor along with provider-specific setup data (such as a
secret and an `otpauth_url` for TOTP) that can be used to display a QR code. The factor must
then be verified via the verify endpoint before it can be used.

**Authentication:** none.

**Request body** (`application/json`)

<TypeList
  types={[
    { name: "provider", type: "`string`", optional: false, description: "The ID of the MFA provider to enroll the factor with (for example, `totp`)." },
    { name: "label", type: "`string`", optional: true, description: "A human-readable label to identify the factor (for example, the name of the authenticator app or device)." },
    { name: "issuer", type: "`string`", optional: true, description: "The issuer name shown in authenticator apps for this factor. Defaults to the application name when omitted." },
    { name: "metadata", type: "`object`", optional: true, description: "Additional provider-specific data to associate with the factor." }
  ]}
/>

**Request examples**

<CodeTabs group="api-sample">
  <CodeTab label="JS SDK" value="js-sdk">

```ts
import Medusa from "@medusajs/js-sdk"

export const sdk = new Medusa({
  baseUrl: import.meta.env.VITE_BACKEND_URL || "/",
  debug: import.meta.env.DEV,
  auth: {
    type: "session",
  },
})

const setup = await sdk.auth.mfa.start({
  provider: "totp",
  label: "Authenticator app"
})

// Render setup.otpauth_url as a QR code or show setup.secret manually.
```

  </CodeTab>
  <CodeTab label="cURL" value="curl">

```bash
curl -X POST 'http://localhost:9000/auth/mfa/factors' \
-H 'Content-Type: application/json' \
--data-raw '{
  "provider": "{value}"
}'
```

  </CodeTab>
</CodeTabs>

**Responses**

`200` OK

`400`, `401`, `404`, `409`, `422`, `500`: an [error response](/api/admin#errors) is returned.

## POST /auth/mfa/factors/\{id\}/verify

**Verify and Enable a Multi-Factor Authentication (MFA) Factor**

Verify a pending multi-factor authentication (MFA) factor by submitting a code generated from
it. A successful verification enables the factor, after which it can be used to verify MFA
challenges during login.

**Authentication:** none.

**Path parameters**

<TypeList
  types={[
    { name: "id", type: "`string`", optional: false, description: "The MFA factor's ID." }
  ]}
/>

**Request body** (`application/json`)

<TypeList
  types={[
    { name: "code", type: "`string`", optional: false, description: "The verification code generated by the MFA factor (for example, the current TOTP code from the authenticator app)." }
  ]}
/>

**Request examples**

<CodeTabs group="api-sample">
  <CodeTab label="JS SDK" value="js-sdk">

```ts
import Medusa from "@medusajs/js-sdk"

export const sdk = new Medusa({
  baseUrl: import.meta.env.VITE_BACKEND_URL || "/",
  debug: import.meta.env.DEV,
  auth: {
    type: "session",
  },
})

const { mfa_factor } = await sdk.auth.mfa.verify("authmfa_123", {
  code: "123456"
})
```

  </CodeTab>
  <CodeTab label="cURL" value="curl">

```bash
curl -X POST 'http://localhost:9000/auth/mfa/factors/{id}/verify' \
-H 'Content-Type: application/json' \
--data-raw '{
  "code": "{value}"
}'
```

  </CodeTab>
</CodeTabs>

**Responses**

`200` OK

`400`, `401`, `404`, `409`, `422`, `500`: an [error response](/api/admin#errors) is returned.

## POST /auth/mfa/recovery-codes

**Generate Multi-Factor Authentication (MFA) Recovery Codes**

Generate a new set of single-use recovery codes for the authenticated user. Recovery codes can
be used to verify MFA challenges when the user does not have access to their primary MFA
factor. Generating new codes replaces any previously issued codes, so they should be stored in
a safe place. At least one enabled MFA factor is required to generate recovery codes.

**Authentication:** none.

**Request body** (`application/json`)

<TypeList
  types={[
    { name: "count", type: "`number`", optional: true, description: "The number of recovery codes to generate. Must be between 1 and 50. Defaults to the provider's configured value when omitted." }
  ]}
/>

**Request examples**

<CodeTabs group="api-sample">
  <CodeTab label="JS SDK" value="js-sdk">

```ts
import Medusa from "@medusajs/js-sdk"

export const sdk = new Medusa({
  baseUrl: import.meta.env.VITE_BACKEND_URL || "/",
  debug: import.meta.env.DEV,
  auth: {
    type: "session",
  },
})

const { recovery_codes } = await sdk.auth.mfa.generateRecoveryCodes()
```

  </CodeTab>
  <CodeTab label="cURL" value="curl">

```bash
curl -X POST 'http://localhost:9000/auth/mfa/recovery-codes'
```

  </CodeTab>
</CodeTabs>

**Responses**

`200` OK

`400`, `401`, `404`, `409`, `422`, `500`: an [error response](/api/admin#errors) is returned.
