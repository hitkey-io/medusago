# {metadata.title}

In this chapter, you'll learn about the architectural layers in MedusaGo.

MedusaGo has the same architecture as Medusa. The layers, the way they depend on each other, and the HTTP API they expose are identical. What changes is the implementation: each layer is written in Go.

## HTTP, Workflow, and Module Layers

MedusaGo is a headless commerce platform. So, storefronts, admin dashboards, and other clients consume MedusaGo's functionalities through its API routes.

In a common MedusaGo application, requests go through four layers in the stack. In order of entry, those are:

1. API Routes (HTTP): API routes are the typical entry point. The server is built on Go's `net/http` package, with a middleware and route stack that matches the behaviour of Medusa's HTTP layer. It can also connect to Redis, which stores the server session data.
2. Workflows: API routes consume workflows that hold the opinionated business logic of your application.
3. Modules: Workflows use domain-specific modules for resource management.
4. Data store: Modules query the underlying data store, which is a PostgreSQL database.

```plain
Storefront / Admin / other clients
              |
              v
   API routes (HTTP layer)
              |
              v
   Workflows (business logic)
              |
              v
   Modules (domain logic and data)
              |
              v
          PostgreSQL
```

<Note>

These layers of the stack can be implemented within [plugins](!docs!/learn/fundamentals/plugins).

</Note>

## Database Layer

The MedusaGo application injects into each module, including your [custom modules](!docs!/learn/fundamentals/modules), a connection pool to the configured PostgreSQL database. Modules use it to read and write data.

MedusaGo only supports PostgreSQL as the underlying database. It talks to it with the [pgx](https://github.com/jackc/pgx) driver and its own data access layer, so the database it reads and writes is the same one that Medusa uses. You can also integrate other databases in a [custom module](!docs!/learn/fundamentals/modules).

<Note>

Modules can be implemented within [plugins](!docs!/learn/fundamentals/plugins).

</Note>

## Third-Party Integrations Layer

Third-party services and systems are integrated through MedusaGo's Commerce and Infrastructure Modules. For other third-party services, create a custom integration in a [custom module](!docs!/learn/fundamentals/modules).

### Commerce Modules

[Commerce Modules](!resources!/commerce-modules) integrate third-party services relevant to commerce or user-facing features through module providers. MedusaGo includes, for example:

- Payment providers: Stripe and Adyen.
- Fulfillment provider: a manual provider.
- Auth providers: email and password, GitHub, and Google.
- Notification providers: a local provider that logs notifications, and SendGrid.

You can replace any of these third-party services to build your preferred commerce ecosystem.

## The Admin Dashboard

The Medusa Admin is a React application that sends requests to the Admin API routes, like any other client. MedusaGo embeds a prebuilt copy of the dashboard in its binary and serves it at `/app` (configurable with the [admin.path](!docs!/learn/configurations/medusa-config#adminpath) option). So you don't deploy the dashboard separately.

If you add [admin customisations](!docs!/learn/fundamentals/admin), `build` compiles the dashboard with your widgets and UI routes. Learn more in the [Build chapter](!docs!/learn/build).

## Full Diagram of MedusaGo's Architecture

```plain
Clients: Storefront (JS SDK / REST), Medusa Admin (/app), other systems
                              |
                  HTTP layer (/store, /admin, /auth, /hooks)
                              |
                          Workflows
                              |
        Commerce Modules                Infrastructure Modules
  (product, cart, order, payment, ...)  (event, workflow engine, locking,
                              |          caching, file, notification, ...)
                              |                     |
                         PostgreSQL        Redis, S3, SendGrid, ...
```
