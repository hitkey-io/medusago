# {metadata.title}

In this chapter, you'll learn what a read-only module link is and how to define one.

## What is a Read-Only Module Link?

Consider a scenario where you need to access related records from another module, but don't want the overhead of managing or storing the links between them. This can include cases where you work with data that isn't stored in your database, such as the records of a third-party system.

Instead of defining a [module link](!docs!/learn/fundamentals/module-links) whose links are stored in a link table, you can use a read-only module link. A read-only module link builds a virtual relation from one data model to another in a different module, without creating a link table. Instead, the ID of the linked record is stored in a property of the first data model.

For example, MedusaGo creates a read-only module link from the `Cart` data model of the Cart Module to the `Customer` data model of the Customer Module. It lets you access the customer of a cart without managing a link: the customer's ID is stored in the cart's `customer_id` property.

---

## How to Define a Read-Only Module Link

The `DefineLink` function takes an optional third parameter with options for the link. To make the link read-only, set its `ReadOnly` field to `true`. You must also set the `Field` of the first data model's side, which is the property that stores the linked record's ID. It needs the side to be a `DefineLinkInput`.

In this example, you define a read-only link from the `post` data model of the Blog Module to the `user` data model of the User Module. You do that by:

- Passing a `DefineLinkInput` as the first side. It holds the linkable and the `Field`, `author_id`.
- Setting `ReadOnly` to `true` in the options.

Unlike a stored link, MedusaGo doesn't create a table for this link. It uses the ID stored in the field of the first data model to retrieve the linked record.

<Note>

A read-only link doesn't support the `Filterable` option. `DefineLink` returns an error if you set it.

</Note>

## Read-Only Module Link Direction

A read-only module link is unidirectional. You can only retrieve the linked record from the first data model. In the example, you retrieve the author of a post, but not the posts of a user.

To retrieve the posts of a user, define another read-only link in the opposite direction.

## One-to-One or One-to-Many?

The records that a read-only link retrieves are one object or a list of objects, depending on the link's options:

- By default, the first data model's field holds one ID, so the link is one-to-one: the property is an object.
- When `IsList` is set, in the first side's `DefineLinkInput` or in the `DefineLinkOptions`, the property is a list.
