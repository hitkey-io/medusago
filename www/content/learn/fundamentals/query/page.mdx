# {metadata.title}

In this chapter, you'll learn about Query and how to use it to fetch data from modules.

## What is Query?

Query fetches data across modules. It's a tool that wraps the [module services](!docs!/learn/fundamentals/modules/service-factory) of the application and the [module links](!docs!/learn/fundamentals/module-links), and it lets you retrieve the records of a data model together with the records linked to it, even when they belong to other modules.

For example, with Query you retrieve a post of the Blog Module with the products of the Product Module that it's linked to, in one call. Query lists the posts, finds their links, and then retrieves the products.

The API routes of the Admin and Store APIs use Query to retrieve their data.

## Querying the Graph

Query's name for the data that you can retrieve is the *graph*: the data models of the modules, and the links between them.

A data model is in the graph when it has an alias, which is the name you pass in `Entity`: every data model of a module has the snake case of its name and its plural, such as `post` and `posts`. The module links add the linked data models as properties of the data models that they link.

## Retrieve Linked Records

Fields can also be properties of the records linked to the data model. Use a dot between the name of the relation and the property: `comments.body`. To retrieve all the properties of a linked record, use `*` after the dot: `products.*`.

The names of the relations are:

- For a relationship of the module, the name of its property: `comments` and `tags` for a post.
- For a module link, the alias of the linked data model: `products` for a post, since a post is linked to many products, and `sales_channels`, `user`, and so on. The [Module Links chapters](!docs!/learn/fundamentals/module-links) explain how the alias is defined.

You can go through many levels:

```go title="src/queries/query.go" file="query/query.go" region="linked"
```

The query above retrieves the posts, their comments (a relationship of the Blog Module), their linked products (a module link to the Product Module), and the variants of the products. Query retrieves each module's data with the module's service, so it makes one request for each module, not one for each record.

A linked record that's a list, such as `comments` or `products`, is a list of records in the result. A linked record that isn't a list is a record, and the property is left out of the result when no record is linked.

### Advanced Query Filters

A filter's value can also be a record with operators:

| Operator | Matches |
| --- | --- |
| `$eq`, `$ne` | Equal, or not equal, to a value. `$ne` with `nil` matches a property that isn't `null`. |
| `$in`, `$nin` | A value that is in a list, or is not. |
| `$gt`, `$gte`, `$lt`, `$lte` | Greater than, greater than or equal to, less than, or less than or equal to a value. |
| `$like`, `$ilike` | A pattern, with `%` as a wildcard. `$ilike` ignores the case. |
| `$re` | A regular expression. |
| `$exists` | A property that's set (`true`) or is `null` (`false`). |
| `$contains`, `$contained`, `$overlap` | For properties that hold lists or JSON: containing, contained in, or overlapping a value. |
| `$not` | Negates an operator. |

The `$and` and `$or` keys combine filters, and `$not` negates one:

## Cache Query Results

If the caching module and the `caching` feature flag are enabled, you can cache the result of a query with the `Cache` option. The `caching.CacheOptions` value has these fields:

| Field | Description |
| --- | --- |
| `Enable` | Enables or disables the cache for this query. The cache is enabled when any other field is set. |
| `Key` | The cache key. By default, MedusaGo computes it from the query. |
| `Tags` | The tags of the cached entry, to invalidate it. |
| `ComputeAutomaticTags` | Whether MedusaGo adds tags from the records that the query retrieves. |
| `TTL` | The time to live of the entry, in seconds. |
| `AutoInvalidate` | Whether the entry is invalidated automatically when its records change. |
| `Providers` | The caching providers to use. |

```go title="src/queries/query.go" file="query/query.go" region="cache"
```

Without the module or the feature flag, the option has no effect, and Query runs the query.

## Query for Your Modules

Query builds the graph at startup from the DML data models of the configured modules and the links that your project defines. A module of your application is in the graph once it's registered in `medusa-config.go`, and its [links](!docs!/learn/fundamentals/module-links) are defined before the application loads. You can then retrieve its data models, such as `post`, with the same calls.

The data models of the graph come from DML definitions: Query can't retrieve data that a module doesn't define as a DML data model.
