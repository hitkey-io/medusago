# {metadata.title}

In this chapter, you'll learn how environment variables are loaded in MedusaGo.

## System Environment Variables

The MedusaGo application loads and uses system environment variables.

For example, if you set the `PORT` environment variable to `8000`, the MedusaGo application runs on that port instead of `9000`.

In production, you should always use system environment variables that you set through your hosting provider. A system environment variable always takes precedence over a value in a `.env` file.

---

## Environment Variables in .env Files

During development, it's easier to set environment variables in a `.env` file in your repository. The [MedusaGo CLI](!resources!/medusa-cli) loads the `.env` file of the directory you run it from before it runs a command, so it applies to `go run . develop`, `db:migrate`, `user`, and every other command.

Based on your `NODE_ENV` system environment variable, the CLI also loads an environment-specific file when it loads your configuration:

<Note title="Tip">

`NODE_ENV` defaults to `production` when you run `start`. Otherwise, it defaults to `development`. Set it explicitly to override the default.

</Note>

A variable is only set if it isn't already set. So the precedence, from highest to lowest, is the system environment, then `.env`, then `.env.<NODE_ENV>`. A value can reference other variables with `$NAME` or `${NAME}`. For example, the installer writes `DATABASE_URL=postgres://localhost/$DB_NAME` in the `.env` file.

To make sure the correct file is loaded as shown in the table, only use `development`, `production`, `staging`, or `test` as the value of `NODE_ENV`.

<Note>

MedusaGo's `.env` handling follows the `dotenv` format: lines such as `KEY=value`, `export KEY=value`, quoted values, and `#` comments.

</Note>

## Use Environment Variables in Your Configuration

Read environment variables in `medusa-config.go` with `os.Getenv`. The CLI loads the `.env` files before it calls your configuration function:

```go title="medusa-config.go" file="project/medusa-config.go" region="config"
```

Some options fall back to an environment variable when you leave them empty, as listed in the next section. You don't need to read those variables yourself.

---

## Environment Variables for Admin Customizations

Since the Medusa Admin is built on top of [Vite](https://vite.dev/), you prefix the environment variables you want to use in a widget or UI route with `VITE_`. Then, you can access or use them with the `import.meta.env` object.

Learn more in the [Admin Environment Variables](!docs!/learn/fundamentals/admin/environment-variables) chapter.

---

You should opt for setting configurations in `medusa-config.go` where possible. For a full list of MedusaGo configurations, refer to the [MedusaGo Configurations chapter](!docs!/learn/configurations/medusa-config).
