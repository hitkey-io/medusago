# {metadata.title}

In this chapter, you'll learn how subscribers receive an event's data payload.

## Access Event's Data Payload

When events are emitted, they're emitted with a data payload.

The `Event` value that the subscriber function receives as a parameter holds the event payload in its `Data` property, with additional context in the `Metadata` property.

For example:

```go title="src/subscribers/product-created.go" file="events/data_payload.go" region="product-created"
```

This logs the product ID received in the `product.created` event's data payload.

The `eventID` function in the example reads the `id` property of the payload. The payload of the events that MedusaGo emits is an object of type `*dal.Record`, so `Data` holds a `*dal.Record`, and you read its values with the `Get` method:

```go title="src/subscribers/product-created.go" file="events/data_payload.go" region="event-id"
```

Since `Data` has the type `any`, check the type of the payload before you use it. The properties of the payload are different for each event.

The `Event` struct has the following properties:

<Note>

The payload and the metadata you receive depend on the event module. With the Redis Event Module, they're decoded from JSON, so the payload is always a `*dal.Record` or a `[]any`. With the Local Event Module, you receive the value that was passed when the event was emitted.

</Note>
